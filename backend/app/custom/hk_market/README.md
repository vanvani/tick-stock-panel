# 港股看板（只读扩展）

给 A 股工作台加一个"邻居窗口"：看港股日线，不参与任何 A 股链路。

```
backend/app/custom/hk_market/   ← 扩展后端（服务 + 路由）
frontend/src/custom/hk/         ← 扩展前端（页面 + 端点封装）
```

在侧栏出现「港股」入口，路由 `/hk`。删掉这两个目录即彻底卸载，核心代码零改动。

## 为什么是独立扩展，而不是让平台支持港股

TSP 的应用层是按 A 股写的：代码规范 6 位、涨跌停 10/20/30%、交易时段 9:30–11:30 + 13:00–15:00、
标的池是 CSI300/CSI500/SSE50、交易日历走 A 股日历、回测按 T+1 撮合。这些假设散落在几十个文件里，
硬改会把每次上游同步都变成解冲突现场。

所以这里只做"取数 + 看"：数据自己拉、指标自己算、页面自己画，一行核心代码都不碰。

## 数据源与能力边界（2026-11 实测）

后端直连 **TickFlow 免费层**（免注册，按 IP 限速 60 次/分）：

| 能力 | 免费层 |
|---|---|
| 港股标的清单 | ✅ 2,849 只 |
| 历史日 K | ✅ 可拉到 500+ 根（约 2 年） |
| 标的名称 | ✅ |
| 实时行情 | ❌ 只有最近一个交易日收盘 |
| 分钟 K | ❌ |

由此带来三个必须让用户看见的口径（已写进 `/meta` 的 notes，页面侧栏也会显示）：

1. **非实时**：页面数字是上一交易日收盘，盘中不更新。
2. **前复权**：价格含分红/拆股调整，和券商软件里的原始价可能有微小差异。
3. **成交额是估算**：免费层 `amount` 字段恒为 0，所以按 `收盘价 × 成交量` 估算，界面一律标「(估)」。

`high_52w` 这类从复权序列取的值会出现长尾小数，服务层统一收敛到 3 位。

## 接口

全部挂在 `/api/custom/hk-market`，只读：

| 端点 | 说明 |
|---|---|
| `GET /meta` | 数据源能力与口径说明、默认篮子 |
| `GET /instruments?q=&limit=` | 按代码/名称搜索（2,849 只本地过滤，不打上游） |
| `GET /quote?symbol=00700.HK` | 单只概览：涨跌幅、振幅、20/60日、年初至今、52周高低、MA、RSI、MACD |
| `GET /kline?symbol=&count=` | 日 K 序列（含指标字段，直接喂 K 线组件） |
| `GET /overview?symbols=a,b,c` | 一篮子概览（最多 24 只），首次拉取受上游限速影响 |

代码格式 `^\d{5}\.HK$`（港股 5 位），传 `700` 之类会得到 400 而不是静默失败。

## 缓存与限速

上游 60 次/分是硬约束，本模块**全局串行 + 1.05 秒最小间隔**（宁可慢也不被限流），
再叠三层缓存把重复请求吃掉：

```
内存（进程内，TTL 6h） → 磁盘 data/custom/hk_market/daily.json（TTL 6h） → 上游
```

因此：**首次**打开页面（默认 6 只自选）约需 6–12 秒，之后是毫秒级；重启进程也不会重新拉。
标的清单另存 `instruments.json`（TTL 7 天）。

## 前端要点

- 自选存 `localStorage` 的 `hk-market:watchlist`，后端不落用户状态（只读扩展不写业务库）。
- 涨红跌绿沿用全站语义色（`text-bull` / `text-bear`）。
- K 线直接复用 `components/EChartsCandlestick`，指标字段名与它对齐（`ma5/ma10/ma20/ma60`、`rsi_14`、`macd_*`）。

## 以后升级方向（按性价比排序）

1. **接付费档位**：拿到实时行情与分钟 K，把 `service.py` 里 `TickFlow.free()` 换成带 key 的客户端即可，页面无需改动。
2. **恒指/国指成份股池**：用 `universes` 接口替代硬编码的 `DEFAULT_BASKET`。
3. **港股通持股 / AH 溢价**：需要额外数据源，属新板块而非本扩展延伸。
